<div align="center"> <h1>WMEval: Evaluating Interactive World Models Grounded on Physical Simulations</h1> </div>
<p align="center"> <a href="https://arxiv.org/pdf/2610.33894"><b>📜 Paper</b></a> | <a href="https://snyhlx.github.io/wmeval-blog/"><b>🌐 Project Page</b></a> | <a href="https://huggingface.co/datasets/lmgame/WMEval-Lite"><b>🤗 Dataset</b></a></p>

WMEval runs the **same action trajectory** in a Unity scene and in a world model, then scores the generated rollout against simulator ground truth (camera poses, object states, momentum and energy, causal event traces) rather than perceptual quality alone. It provides:

- **9 Unity scenes** (`BallRoller`, `BeamDomino`, `BilliardGame`, `ChessBoard`, `LiquidContainer`, `MirrorRollingBall`, `RacingCar`, `SunRisesAndSets`, `WanderingGarden`) with designed action trajectories.
- **WMEval Lite**, a Unity-free suite: checksummed case bundles (conditioning frame, prompt, actions, reference rollout, Unity quantities) and one CLI that validates, evaluates and aggregates. The paper's Table 4/7 cells are Lite cases.
- **Standardized trajectories** compiled onto each backend's native interface, with explicit action targets, calibration and unsupported-control reporting.

## Installation

```
git clone https://github.com/hao-ai-lab/WMEval.git && cd WMEval
# macOS (Apple silicon)
uv venv --python 3.11 .venv && uv pip install --python .venv/bin/python -r requirements-macos.lock
# Linux + NVIDIA GPU: creates .venv-gpu and checks it; runs every dimension
bash scripts/bootstrap_tables_4_7_gpu.sh
```

Case metadata (`case.yaml`, checksums) lives in this repo; case data is on the Hub at [`lmgame/WMEval-Lite`](https://huggingface.co/datasets/lmgame/WMEval-Lite) (public, no token), pinned to `eval_sets/wmeval_lite_v1/DATASET_REVISION`:

```
python tools/sync_lite_data.py download        # add --split full for the 220 synthetic trajectories
python tools/run_wmeval_lite.py validate --suite eval_sets/wmeval_lite_v1
```

VLM-judged dimensions need `OPENAI_API_KEY`; CV dimensions fetch pinned checkpoints on first use (`experiments/tables_4_7/evaluator_assets.lock.json`). The data is git-ignored; `git config core.hooksPath .githooks` warns when a checkout needs a re-download.

## Quick Start

Generate one video per case and seed at `<model_root>/<Scene>/<variant>/<seed>.mp4` (or list them in a JSONL `--candidate-manifest`), then:

```
python tools/run_wmeval_lite.py list-cases --suite eval_sets/wmeval_lite_v1
python tools/run_wmeval_lite.py run --suite eval_sets/wmeval_lite_v1 \
  --model-root runs/<model> --output-dir reports/wmeval_lite/<model> --resume
```

`--dimensions` selects a subset; `--split full` adds the synthetic trajectories, reported apart from the core headline. Outputs: `per_case_results.jsonl` (one row per dimension × case × seed, with the case's evaluator lock), `aggregate_summary.json` (seed means per case, then across cases) and `aggregate_summary.csv`. A headline needs 5 seeds per applicable case, otherwise it is kept as `provisional_value`. Models that draw a HUD set `shadow_hud_preset` (`lingbot`, `mg2`, `mg3`, `genie`) for the lighting case. On Modal, `modal run tools/run_wmeval_lite_modal.py::main --model-root /cand/<model>`; `tools/generate_waypoint15_candidates_modal.py` generates candidates from the bundles without Unity.

| Task | Command |
| --- | --- |
| Jobs and N/A cases for a new model | `tools/expected_jobs.py --model <name> --output runs/<name>` · [`TEMPLATE.md`](tools/model_adapters/TEMPLATE.md) |
| Environment check | `tools/preflight_lite.py --device <cuda\|mps\|cpu>` |
| Compare with the paper's Table 4/7 | `tools/export_lite_table_results.py` → `tools/compare_table_results.py compare` |
| Hosted judge via a gateway | `tools/judge_gateway.py --key-file <key> -- <args>` |
| Rebuild the leaderboard | `tools/build_leaderboard.py ... --readme README.md` (full command in its docstring) |

## Evaluation Dimensions

Each dimension compares quantities recovered from the candidate video with those logged by the Unity twin. Pipelines, flags and caveats: [docs/evaluation_dimensions.md](docs/evaluation_dimensions.md).

| Dimension | Question | Headline metrics | Cases | Needs |
| --- | --- | --- | --- | --- |
| [Consistency](docs/evaluation_dimensions.md#environment-object--character-consistency) | Do objects, layout and character identity persist as the camera leaves and returns? | Depth AbsRel ↓, pairwise-distance MAE ↓, DINOv2 character consistency ↑ | 16 | CV |
| [Action Controllability](docs/evaluation_dimensions.md#action-controllability) | Does motion follow the commanded action? | GT-RAFT relative EPE ↓ / cosine ↑; synthetic-flow cosine ↑ | 3 | CV |
| [Kinematics & Mechanics](docs/evaluation_dimensions.md#kinematics--mechanics) | Do matched controls give simulator-consistent trajectories? | DTW ↓, FDE ↓, momentum/energy robust error ↓ | 3 | CV |
| [Fluid Mechanics](docs/evaluation_dimensions.md#fluid-mechanics) | Does liquid in a moving bottle slosh like the reference? | Area jitter ↓, surface tilt ↓, slosh-spectrum L1 ↓ | 4 | CV |
| [Physical Causality](docs/evaluation_dimensions.md#physical-causality) | Does an action propagate through a multi-stage causal chain? | Causal success rate ↑, ICRA, DUA (deltas from Unity) | 3 | VLM |
| [Lighting & Shading](docs/evaluation_dimensions.md#lighting--shading) | Do shadows stay consistent with one light source? | Multi-object sun disagreement ↓, shadow jitter / area / shape drift ↓ | 1 | CV |
| [Prompt-Scene Consistency](docs/evaluation_dimensions.md#prompt-scene-consistency) | Does the rollout match its scene description? | Environment / object / overall rubric ↑ (ρ = 0.90 with humans) | 6 | VLM |
| [Perceptual Similarity](docs/evaluation_dimensions.md#perceptual-similarity-lpips) | How close is the rollout around matched contact events? | Causal LPIPS ↓ | 7 | CV + VLM |

Unity self-match floors: [`SELF_MATCH_BOUNDS.md`](eval_sets/wmeval_lite_v1/SELF_MATCH_BOUNDS.md); differences from the paper: [`DIFFERENCES_FROM_PAPER.md`](eval_sets/wmeval_lite_v1/DIFFERENCES_FROM_PAPER.md). Optional CLIP4Clip, DiffusionLight and GroundingDINO tools: [docs/additional_evaluators.md](docs/additional_evaluators.md).

## WMEval Lite Suite

`eval_sets/wmeval_lite_v1/suite.yaml` is the single source of truth for case wiring. The `test_core` split has **32 cases across 9 scenes and 8 dimensions** (43 case–dimension pairs), including the 14 Table 4/7 cells (`<Scene>/scene_<variant>`, `<Scene>/kinematics_<view>`).

```
cases/<Scene>/<variant>/
  case.yaml                 # prompt, modules, protocol, evaluator lock (in repo)
  reference/                # from the Hub, except checksums.sha256
    reference.mp4, ref.png  # reference video; conditioning frame if not frame 0
    artifacts/              # actions.txt, action.npy/npz, trajectory.yaml, rubrics, QA, liquid masks/flow
```

`tools/build_lite_case.py` (re)builds a case and its lock; `tools/sync_lite_data.py upload` publishes data (maintainers).

**Action trajectories.** Table 4/7 cases carry a canonical semantic `trajectory.yaml` (typed channels, units, segments) and its compiled forms; `tools/build_table_lite_cases.py` rebuilds them from the hash-locked trajectories in `experiments/tables_4_7/trajectories/`. Backends are declared once in `experiments/tables_4_7/action_backends.yaml`: the entity each trajectory actuates (`camera`, `ego_vehicle`, `cue_ball`, ...), each backend's native timeline and calibration, and which targets it cannot express. Input preparation (`tools/prepare_table_trajectories.py`, `prepare_matrix_game_inputs.py`, `prepare_lingbot_table7_inputs.py`) refuses an unsupported target/backend pair rather than substitute another control.

| Backend | Native input | Camera | Vehicle / ball |
| --- | --- | --- | --- |
| Unity | runtime arguments | reference | reference |
| Project Genie | browser keys | nominal (left turn 51.47 °/s) | nominal key rules |
| Matrix-Game 2.0 | 129 frames @ 12 fps, keys + mouse | 10.1 °/mouse unit/frame | thresholded WASD |
| Matrix-Game 3.0 | 177 frames @ 17 fps, keys + mouse | regime-specific gains | out of scope |
| LingBot-World Base Cam | 161 camera poses @ 16 fps | nominal poses | unsupported |

**Synthetic trajectories (`test_full`).** 220 trajectories (252 rows with the core cases) built text first: each is an action description from a per-target step vocabulary (*"the camera turns left at 30°/s for 2 s, then holds still"*) that completes a core case's prompt and compiles to a schema-v1 `trajectory.yaml`, starting from that case's conditioning frame. Each has a Unity reference rendered by replaying the actions; plans whose reference cannot give a meaningful score are screened out and replaced deterministically ([`AUDIT.md`](eval_sets/wmeval_lite_v1/AUDIT.md)). Synthetic rows are scored like their conditioning case and aggregated in a separate `synthetic` block.

| Family | Target | # | Steps (core case) |
| --- | --- | --- | --- |
| `camera_yaw` | camera | 45 | turn, hold, sweep, half turn (9 scene views) |
| `camera_orbit` | camera | 20 | circle cw / ccw, pause (`SunRisesAndSets/lighting`) |
| `ego_vehicle` | vehicle | 28 | drive, steer, lane change, brake (`RacingCar/kinematics_third`) |
| `cue_ball` | cue ball | 25 | strikes in 8 directions × 3 strengths (`BilliardGame/kinematics_first`) |
| `ball_force` | ball | 28 | pushes in 8 directions × 2 strengths (`BallRoller`, `MirrorRollingBall`) |
| `beam_domino` | ball | 25 | rolls forward / angled / sideways (`BeamDomino/causal`) |
| `liquid_container` | bottle | 25 | jolts, slides, shakes, rests (`LiquidContainer/fluid_rest`) |
| `character` | character | 24 | walk in 8 directions, sprint, jump (`ChessBoard/walk_third`) |

Maintainer commands for rendering references and reference inputs (Unity editor required) are documented in `tools/render_synthetic_references.py` and `tools/build_synthetic_reference_inputs.py`.
